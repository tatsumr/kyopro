# Fast Set （64分木）の解説
[Fast Set](https://github.com/tatsumr/kyopro/blob/main/ds/fastset.md) の仕組みを説明する。

## ナイーブなアイデア
葉には $N$ 個の頂点があり、 $i~(0 \le i \lt N)$ 個目の頂点の値は要素 $i$ が存在するとき $1$ 、存在しないとき $0$ である。葉以外の各頂点の値は、高々64個の子の中に値が $1$ の頂点が1つでもあれば $1$ 、すべての子の値が $0$ なら $0$ である。（すなわち子頂点たちの値の bitwise OR をとっている。）

深さごとに頂点 $0, ~ 1 ~ ,...$ と番号をつけるとすると、葉でない深さ $d$ の頂点 $i$ は、深さ $d+1$ の頂点 $[64i,~64(i+1))$ を子に持つ。

## bit演算によるメモリ省略
各頂点の値は $0$ または $1$ なので、1ビットで表せる。そこで、木を64ビット整数の二次元配列 `vector<vector<unsigned long long>> seg` で表現する。ここで、 `seg` は実装の都合上通常の根付き木とは上下が逆になっている。すなわち葉の頂点たちは `seg[0]` で、添字が大きくなるほど根に近づく。

このとき、
- ナイーブなアイデアでの木で（深さによらず）頂点 $i$ だったものは `seg[*][i/64]` の $i\bmod 64$ ビット目に対応している。
-  `seg[d][i]` の $b$ ビット目にあたる頂点の子は、 `seg[d-1][64i+b]` の各ビットにあたる頂点たちである。
-  `seg[d][i]` の $b$ ビット目にあたる頂点の親は、 `seg[d+1][i/64]` の $i\bmod64$ ビット目にあたる頂点である。

## insert
集合に要素 $x$ を追加する際は、 $x$ に対応する葉のノードから根のノードまで、順に対応するビットを立てていく。

例えば $4159$ を追加する際は以下のような処理が行われる。
1. `seg[0][64]` の $63$ ビット目を立てる。
2. `seg[1][1]` の $0$ ビット目を立てる。
3. `seg[2][0]` の $1$ ビット目を立てる。
4. `seg[3][0]` の $0$ ビット目を立てる。

## erase
集合から要素 $x$ を削除する際も、 `insert` と同様に $x$ に対応する葉のノードから順に親へ移動して処理していく。
この時、葉以外のノードは単に対応するビットを下ろせばいいというわけではない点に注意する。
葉以外のノードの値は子ノードたちの bitwise OR なので、子ノードが $1$ つ $0$ になったとしてもビットが立っている子ノードが $1$ つでもあれば親ノードの値は $1$ のままだからである。
実装では、更新後の子ノードたちの bitwise OR の値を `y` で管理し、この `y` を親ノードの対応するビットに反映させることで更新処理を正しく行えるようにしている。
